  воскресенье с 22:05, пятница до 20:58.

## 2. Правила работы (действуют для всех)

- Изменения в ботах сначала обсуждаются с владельцем, потом делаются. По завершении — отчёт.
- Только демо-счёт. Не запускать непроверенные установщики.
- Данные для проверок — 2024–2026. **Всё до 2026-10-15 уже просмотрено** (подбор и контроль).
- **Холдаут — с 2026-10-16 00:00 UTC** (`docs/oos-protocol.md`): никто не смотрит этот участок
  (цены, тики, отчёты, бэктест), пока стратегия не записана заранее (предрегистрация в
  `docs/prereg/`). Прогон по холдауту — один раз, без подстройки после цифр.
- Черновик критериев приёмки на холдауте (ещё не подтверждён владельцем): ≥ 100 сделок;
  нижняя граница 95 % бутстрэп-интервала PF в R > 1.0; просадка по средствам не глубже 15 %;
  стрессы (спред +0.20 и +0.50 USD, задержка 500 мс) тоже с нижней границей PF > 1.0.
- Скрины из закрытых каналов и чужие сделки в репозиторий не класть.
- Отвечать по-русски.

## 4. Что предложил владелец (суть запроса)

Цель — повысить прибыльность. Предложения (из сообщения владельца, близко к тексту):

1. **Не подгонять параметры, а фильтровать сигналы по режиму рынка.**
   - Фильтр тренда D1 сделать обязательным, а не опциональным (у Alchemist он сократил сделки
     на 35–40 %, но улучшил PF и просадку).
   - Добавить фильтр волатильности: торговать только при ATR выше порога (пробойные стратегии
     теряют в консолидации).
2. **Объединять ботов не «сшиванием» кода, а через оркестратор.**
   - Вынести логику каждого бота в класс (`CAlchemistStrategy`, `CAsiaBreakoutStrategy`).
   - Главный класс `CPortfolioManager`: следит за корреляцией (не открывать одну сторону по
     связанным инструментам, например золото и серебро), ограничивает общую просадку
     (остановка всех стратегий), распределяет риск (например, 1 % на сделку на бота).
   - Пример такой архитектуры — проект **Argus**.
3. **Диверсификация по типам стратегий:** у нас в основном пробойные и трендовые; добавить
   **возврат к среднему** для боковика.
4. **Ориентиры:** Argus (+125 % за 8.3 года, PF 1.18, просадка −36 %, архитектура из трёх
   уровней), коллекция **GeneralTradingSarl/expert-mt5**, статья MQL5 об оценке портфеля с
   учётом корреляции, «исследование 312 советников»: медианный PF на реальных тиках падает с
   2.46 до 0.92 против OHLC — значит, проверка на реальных тиках Exness — верный путь.
5. Просьба: дать мнение, составить план тестов и, возможно, новых ботов; изучить названные
   проекты целиком и взять оттуда всё полезное.

## 5. Мнение Claude по каждому пункту

1. **Фильтр D1 обязательным для всех — нет.** У Alchemist он уже включён по умолчанию, там он
   проверен. Конструктор проверил его на всех остальных входах — пользы нет, у FVG хуже.
   Фильтр ставим только там, где он доказан, иначе это та же подгонка.
2. **Фильтр волатильности — да, проверить.** Это новое. Порог только **относительный**
   (ATR против его средней или медианы): ATR золота в 2025–2026 вырос примерно вдвое,
   абсолютный порог сломается. Частично он уже есть: коробка Азии не меньше 3 USD.
3. **Оркестратор в виде одного советника — пока преждевременно.**
   - Инструмент один (XAUUSDm), корреляция «золото против серебра» нам сейчас не нужна.
   - Реальный портфельный риск — **одновременные покупки золота** у Alchemist и пробоя Азии.
   - Общий лимит риска счёта уже есть (`AccountRisk`, `MaxAccountRiskPercent`) и «страж счёта»
     в Alchemist (`RiskGuard`: риск 0.5 %, стоп дня −2 %, полная остановка −15 %).
   - Склейка стратегий в один советник добавит ошибок и усложнит сверку демо с тестером.
   - Порядок: сначала посчитать портфель на истории; лёгкий слой (общий флаг остановки и
     лимит позиций в одну сторону) — только если расчёт покажет пользу.
4. **Возврат к среднему — идея верная, но в другой форме.** Все входы против движения у нас
   провалились. Не проверен **откат по тренду** (покупка просадки при восходящем тренде) —
   механически это возврат к среднему, но по направлению тренда. Чистый возврат к среднему во
   флэте проверить быстро, ожидания низкие.
5. **Публичные решения — источник идей, не ориентир.** У Argus найдены заглядывание в будущее
   и подбор на всех периодах (раздел 6.1). 10 % в год при просадке 36 % — слабый результат.
   «Исследование 312 советников» найти не удалось: числа 2.46 и 0.92 — из двух разных частных
   примеров. Сам вывод (реальные тики сильно режут результат) подтвердился нашим аудитом.
6. **Главное ограничение — данные, а не идеи.** Всё до 2026-10-15 просмотрено, чистый участок
   растёт примерно на неделю в неделю. Новые идеи проверяем только на старых данных с
   поправкой на перебор; финалистов — по предрегистрации, один раз на холдауте. Самое ценное
   сейчас — демо-форвард и накопление холдаута.

## 6. Разбор внешних проектов (кратко; подробно — `docs/external-review.md`)

### 6.1. Argus (github.com/logiccrafterdz/Argus)

20 советников MQL5 + бэктестер на Python, 10 инструментов (золото есть), 2018 — май 2026.

**Полезные идеи:**
- Отдельный советник-диспетчер на одном графике: считает просадку дня / недели / месяца
  (3 / 8 / 15 %) и поднимает глобальную переменную терминала «стоп»; остальные советники перед
  входом её читают. Так же рассылаются режим рынка и сессия. Стратегии остаются отдельными.
- Лимит позиций в одну сторону по символу от всех советников (`IsExposureSafe`).
- Снижение лота при просадке: 1.0 → 0.5 → 0.25 → 0.1 → 0 при просадке от пика 1.5 / 3 / 5 /
  8 %, пик за 30 и 126 дней (берётся худший).
- Режим рынка: ADX(14) > 25 — тренд, ≥ 45 — «истощение»; ATR(14) / SMA20(ATR) > 1.3 —
  расширение, < 0.7 — сжатие. Стратегия объявляет режимы и сессии, где работает.
- Стратегия TrendPullback (правило в 7.5).

**Почему их цифрам не верим:** точки разворота подтверждаются будущими барами, а сигнал их уже
использует (TrendPullback, Hidden Divergence); 10+ прогонов с правкой стратегий на всех
периодах, три активные выбраны из 20 по результатам; прибыль теста в основном за март–апрель
2025; отрицательный Шарп при положительной доходности.

### 6.2. expert-mt5 (github.com/GeneralTradingSarl/expert-mt5)

1185 файлов `.mq5`, почти все — старые примеры из MQL5 CodeBase; README по шаблону, результатов
нет, «оптимизированы» без подтверждения; 259 требуют отсутствующих индикаторов. Полезны идеи:
**Larry Connors RSI 2** (правило в 7.6), **Hans123** (тот же пробой утреннего диапазона, что у
нас), **Indiana Jones** (новый минимум 200 баров → покупка к среднему; чистый возврат к
среднему).

### 6.3. Статья MQL5 «Correlation-Aware Multi-EA Portfolio Scorer» (articles/21955)

Корреляция дневного P&L между советниками + покрытие часов и дней + классы активов → оценка
A+ … F (веса 50 / 25 / 25 %; |r| < 0.35 хорошо, ≥ 0.6 опасно). Изъяны: дни сопоставляются по
номеру строки, а не по дате; отрицательная корреляция штрафуется; общая просадка портфеля не
считается. Берём идею, считаем правильно (7.1).

### 6.4. Статьи о золоте (блоги MQL5)

- **«49 000 вариантов правил»** (blogs/post/779464): устояла **вечерняя покупка золота** —
  покупка в 18:00 по Нью-Йорку, продажа в 03:00 (9 часов), вечера пн–чт; XAUUSD Deriv,
  2011 — октябрь 2026, 2489 сделок, +2.74 б.п. на сделку после свопа (t 2.86); первые 60 %
  истории ≈ 0, последние 40 % +5.49 б.п. Формальной поправки на перебор нет. Правило в 7.8.
- **«43 советника на золоте»**, **«год тестов на реальных тиках»** (posts 773167, 774275;
  автор продаёт свои советники): узкие стопы и маленькие тейки на реальных тиках умирают,
  выживают широкие стопы по ATR; узкие временные окна быстро теряют преимущество; проверять
  на двух источниках данных, смотреть просадку по средствам. Совпадает с нашим аудитом.

## 7. Новые идеи — точные правила для проверки

Общие условия для всех проверок шагов 1–4: только данные **до 2026-10-15**; периоды подбора —
2024, 2025, январь–май 2026; июнь — 15 октября 2026 уже просмотрен (использовать как
«сравнение», не как чистый контроль); спред 0.25 USD, своп покупки по спецификации; одна
позиция на сочетание; результат в R; сравнение со случайными входами; поправка на перебор —
максимум z по всем испробованным сочетаниям (как в `constructor.py`).

### 7.1. Портфель на истории (без изменения ботов)

- **Входные данные:** списки сделок за 2024 — 2026-10-15 для: Alchemist H1 выход 12 (код),
  Alchemist «только покупки, выход 24», пробой Азии (новые настройки: 5R, 120 ч), канал H4 со
  стопом 3 ATR. Источник — Python (`constructor.py` / `research/backtester`) и, где есть,
  отчёты MT5.
- **Считаем:**
  - дневной результат каждого бота **по календарным датам** (день без сделок = 0);
  - корреляция Пирсона дневного результата по парам и скользящая за 60 дней;
  - доля времени, когда позиции двух ботов открыты одновременно **в одну сторону**, и
    суммарный риск в такие моменты;
  - общая кривая, просадка по средствам, худший месяц, доходность / просадка при риске 1 %
    на сделку у каждого бота;
  - варианты распределения риска: поровну; обратно волатильности дневного результата;
    1 % только самому сильному + 0.5 % остальным.
- **Ответ:** снижает ли комбинация просадку относительно отдельных ботов; нужен ли общий
  лимит риска и какой порог (например, `MaxAccountRiskPercent` = 2–3 %).

### 7.2. Снижение лота при просадке (из Argus)

Множитель риска по худшей просадке от пика за 30 и 126 дней: < 1.5 % → 1.0; < 3 % → 0.5;
< 5 % → 0.25; < 8 % → 0.1; иначе 0; после глубокой просадки — 0.25, как только эквити выросла
на 3 % от дна. Проверить на кривой портфеля из 7.1: меняется ли доходность / просадка. Такие
правила часто режут доход сильнее, чем просадку, — принимать только по цифрам.

### 7.3. Лимит позиций в одну сторону и общий флаг остановки (из Argus)

Только если 7.1 покажет, что одновременные покупки — заметная часть риска:
- лимит: не больше N позиций (или суммарного риска X %) в одну сторону по XAUUSDm от всех
  ботов; проверяется в общем модуле перед входом (`Include/Core/AccountRisk.mqh`);
- общий флаг: глобальная переменная терминала «стоп», которую поднимает любой бот при
  срабатывании стража счёта; остальные боты её читают. Отдельный советник-диспетчер не нужен.

### 7.4. Фильтр волатильности

Три варианта, каждый — выкл. / только выше / только ниже:
- `vol20`: ATR(14) / SMA20(ATR) рабочего ТФ — расширение > 1.3, сжатие < 0.7 (как в Argus);
- `vol100`: ATR(14) D1 / медиана ATR(14) D1 за 100 дней — выше / ниже 1.0;
- для пробоя Азии: размер коробки в ATR(14) D1 (≥ 0.2 / 0.3 / 0.4) вместо порога 3 USD.

Добавить в конструктор как новое измерение фильтров и прогнать на всех живых входах
(Alchemist H1/H2/H4, пробой Азии, канал H4, FVG H1).

### 7.5. Откат по тренду (по мотивам Argus TrendPullback, без заглядывания в будущее)

- ТФ: H1 и H4.
- Тренд вверх: EMA50 > EMA200 и EMA200 выше, чем бар назад; два последних **подтверждённых**
  минимума растут (точка разворота с радиусом k считается известной только через k баров после
  неё).
- Откат: минимум позапрошлого закрытого бара ≤ EMA50.
- Вход: закрытие прошлого бара выше максимума позапрошлого → покупка по рынку на открытии
  следующего бара. Продажи — зеркально.
- Стоп 2 ATR(14); выходы — стандартный набор конструктора (тейк 3 / 5 / 10R, половина на 2R +
  6R, по времени 12 / 24 ч, трейлинг). Фильтр D1 — как измерение конструктора, не обязательно.

### 7.6. Connors RSI(2)

- ТФ: H1 и H4 (оригинал — H1 на форексе, классика — D1 на акциях).
- Покупка: закрытие выше SMA200 и RSI(2) < 6 (варианты 5 / 10). Продажа: закрытие ниже SMA200
  и RSI(2) > 95 (варианты 90 / 95).
- Выход: закрытие выше SMA5 (для продажи — ниже), плюс защитный стоп 2–3 ATR и предел по
  времени; также стандартные выходы конструктора.
- Ожидание: тренд золота 2024–2026 вверх, поэтому покупки должны быть лучше продаж — проверять
  стороны отдельно.

### 7.7. Возврат к среднему во флэте (быстрая проверка)

- Покупка при закрытии ниже нижней линии Боллинджера (20, 2) только если ER(D1, 20) < 0.3
  (флэт по `MarketRegime`); продажа — зеркально у верхней линии.
- Выход на средней линии или по R; стоп 1.5–2 ATR.
- По прошлым проверкам ожидаем проигрыш; если так — закрыть тему «против движения» окончательно.

### 7.8. Вечерняя покупка золота (из блога MQL5)

- Правило автора: покупка в 18:00 по Нью-Йорку, продажа в 03:00 по Нью-Йорку, вечера
  понедельника — четверга (пятница исключена).
- **В UTC (время сервера Exness):** летом США (EDT) вход 22:00 UTC, выход 07:00 UTC; зимой
  (EST) вход 23:00 UTC, выход 08:00 UTC. Летом вход совпадает с открытием торговли после
  перерыва (22:01 UTC) — там самый широкий спред, вход надо сдвигать на первый тик после 22:01
  или на 22:05–22:15.
- **Своп:** позиция переходит через 00:00 UTC, значит, каждая сделка платит своп покупки
  ≈ 0.49 USD на унцию (≈ 1.2 б.п. при цене 4000), в среду тройной (≈ 3.7 б.п.). У автора
  преимущество +4.4 б.п. до свопа — у Exness своп может съесть большую часть; учитывать точно.
- Проверка: 2024 — 2026-10-15 на минутках (Python), с реальным спредом по часам
  (`research/backtester/data/exness-xauusd-spread-ny-2026.json`) и свопом. Важно: этот период
  входит в период поиска автора, поэтому положительный результат у нас — ещё не независимое
  подтверждение. Независимая проверка — только холдаут с 2026-10-16 по предрегистрации.

**Критерии прохождения на шагах 3–4** (как в конструкторе): средний R > 0 во всех трёх
периодах подбора (не меньше 20 сделок в каждом), лучше случайных входов (p ≤ 0.05) и проходит
поправку на перебор (p_max ≤ 0.10). Если не проходит никто — отвечаем «нет», а не ослабляем
порог. Прошедшие — в тестер MT5 и сверка с Python, затем предрегистрация.

**Порядок:** 1 → 2 (дешёвые и нужны для демо) → 3 → 4 → 5 → 6; шаг 7 — как только владелец
даст машину и подтверждение.

## 9. Открытые вопросы к владельцу

1. **Демо-форвард:** есть ли постоянно включённая машина (VPS или домашний ПК с MT5) и
   демо-счёт с балансом около 10 000 USD? Какие боты ставить: только Alchemist long24 или ещё
   пробой Азии?
2. **Риск пробоя Азии:** в коде по умолчанию 3 %, все тесты при 1 %. Снизить по умолчанию до 1 %?
3. **Критерии приёмки холдаута** (раздел 2) — подтвердить или поправить цифры.
4. **Объединение в один советник:** согласен ли сначала обойтись общим модулем риска (флаг
   остановки + лимит позиций в одну сторону), а один советник-оркестратор делать, только если
   этого не хватит?
5. **Новые инструменты** (серебро, индексы) — нужны ли? Только тогда контроль корреляции
   между инструментами из предложения владельца станет актуален.
