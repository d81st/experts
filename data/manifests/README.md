# Манифесты тиков

Сырые тики в git не коммитятся. Сюда можно положить только `manifest.json` после прогона
(контрольные суммы и границы файлов, без котировок и без журналов терминала).

Прогон с ветки `grok`: правка `data/export-request.json` (`"run": true`, символ и даты)
и пуш в `grok`. Другие коммиты этот файл не меняют, поэтому съём не стартует.
`"run": false` или удаление файла тоже не запускает терминал.
`workflow_dispatch` в том же файле сценария остаётся для запуска из вкладки Actions,
когда сценарий есть на ветке по умолчанию; с одной только `grok` GitHub его не принимает.
Скрипт `tools/tick-export.mq5` на том же Exness MT5, что и `backtest.yml`, снимает
`CopyTicksRange(..., COPY_TICKS_ALL)` окнами по суткам (окно делится, если не хватает памяти)
и пишет месяц в CSV: `time_msc,bid,ask,last,volume,volume_real,flags`.

`time_msc` — часы сервера брокера, миллисекунды с 1970-01-01, без пересчёта пояса.
На сервере Exness этого репозитория часы совпадают с UTC.

## Куда девается архив

Артефакт GitHub Actions `ticks-<symbol>-<from>-<to>`: `*.csv.gz`, `manifest.json`,
`validation.json`, `export_info.txt`. Журналов терминала там нет.

Это транспорт одного прогона, не постоянное хранилище:

- у публичного репозитория артефакт живёт не дольше 90 дней;
- у GitHub Free в квоту входит 500 МБ артефактов на аккаунт;
- месяц тиков XAU после gzip — десятки–сотни МБ, 2024–2026 целиком туда не влезает;
- job обрывается через 6 часов, поэтому длинный диапазон лучше резать по несколько месяцев.

`publish_release=true` кладёт те же файлы (и только их) в релиз с тегом
`tick-archive/<symbol>/<from>_<to>/r<run id>`. Файл релиза — до 2 ГБ, тег не перезаписывается:
повторная выгрузка тех же дат — новый тег, потому что брокер дозаливает историю задним числом.
По умолчанию релиз не создаётся.

Отдельный пререлиз `data-ticks-XAUUSDm-2026-v1` собирается сценарием
`publish-tick-release.yml` из уже готовых артефактов (без нового съёма),
когда меняется `data/tick-release.json` и в нём `"run": true`.
Тег указывает на коммит `grok` и помечен как prerelease, поэтому не становится Latest.
В релиз попадают только `ticks_XAUUSDm_2026-*.csv.gz`, общий `manifest.json`,
`SHA256SUMS` и `validation-*.json`.

В ветку `tester-results` тики не пушатся: там уже лежат журналы со счётом и IP.

## Поля манифеста

На каждый `*.csv.gz`: `symbol`, `month`, `row_count`, `first_time_msc`, `last_time_msc`,
`first_timestamp`, `last_timestamp` (те же серверные часы), `sha256` (байты gzip),
`export_date`, `terminal_build`, `terminal_name`, `broker_company`.
Номера счёта, имени сервера и IP в манифесте нет.

`validation.json` — отдельный отчёт прогона: пустые месяцы до начала истории,
каждый гэп длиннее порога вне суточной паузы (~45–100 минут между 20:50 и 23:25)
и уикенда (пятница вечером — воскресенье), не выборка, `bid>ask`, неположительные bid/ask,
повторы полностью одинаковых строк, число повторов одной миллисекунды с разными ценами,
расхождение числа строк со скриптом.
`earliest_tick_msc` — первый тик, который терминал отдал от 2000-01-01, даже если он
раньше запрошенного окна. Одинаковая миллисекунда с разными ценами сама по себе не ошибка.
`last` и `volume` у CFD часто нули — это не брак.

Проверка упаковщика без терминала: `python3 tools/validate_ticks.py --self-test`.
