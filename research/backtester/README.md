# Тиковый бэктестер XAUUSD

Независимая модель исполнения. Тестер MetaTrader сюда не входит: ни его сделки,
ни его индикаторные буферы, ни его отчёты не считаются истиной. Отчёты в
`tester-results` нужны только как внешняя сверка.

Запуск и тесты — из этого каталога:

```bash
cd research/backtester
python3 -m pytest
python3 -m backtester.cli alchemist --help
python3 -m backtester.cli compare --help
```

Зависимостей у ядра нет. Чтение parquet (Dukascopy) требует `pyarrow` 14–17
(`pip install 'pyarrow>=14,<18'` рядом с numpy 1.x). Тесты — pytest.

Сырые тики в репозиторий не кладутся. В `tests/fixtures` только короткий HTML
отчёта на несколько строк.

## Поток тиков

Один тип `Tick`: `time_msc` (UTC, миллисекунды), `bid`, `ask`.

- Exness: `csv.gz`, колонки `time_msc,bid,ask,last,volume,flags`
  (`volume_real` допустим и не обязателен). Время сервера Exness — UTC+0,
  своего перехода на летнее время нет. Реальные тики XAUUSDm у брокера есть
  с 2026-01-01.
- Dukascopy: parquet (zstd), колонки `time_msc,bid,ask,bid_vol,ask_vol`.

Файлы читаются по порядку путей. `end_msc` исключительный: тик на границе
и всё, что позже, не отдаётся. Время, идущее назад, обрывает поток.

Поправка котировки (сначала ширина спреда, потом сдвиг уровня):

```text
mid  = (bid + ask) / 2
half = (ask - bid) * spread_multiplier / 2
bid' = mid - half - spread_addon / 2 + price_offset
ask' = mid + half + spread_addon / 2 + price_offset
```

`spread_addon` расширяет спред вокруг середины. `price_offset` сдвигает обе
стороны. Пример: bid 100, ask 100.4, множитель 2, добавка 0.2, сдвиг 0.2 →
bid 99.9, ask 100.9. Если после поправки bid > ask, прогон останавливается.

Чтобы прикинуть Exness на архиве Dukascopy, типичная пара — `price_offset=0.2`
и `spread_addon` под нужный спред. Медиана спреда Dukascopy по годам: 0.39 /
0.60 / 0.68 USD в 2024 / 2025 / 2026. Это ориентир, не подгонка под отчёт.

## Бары

M1, M2, M5, M15, M30, H1, H2, H3, H4, H6, H8, H12, D1. Сетка от эпохи UTC.
Тик ровно на границе открывает новый бар и в предыдущий не попадает.
Пустой интервал бара не создаёт. OHLC — bid, ask копится отдельно.

Стратегия видит только закрытые бары. На общей границе сначала закрывается
старший таймфрейм, потом младший. Прогрев (`--warmup-m1`, CSV
`time,open,high,low,close` по bid) подмешивает бары, которые полностью
закрылись до первого тика.

## Заявки и защита

Рынок, лимит, стоп, SL, TP, срок жизни заявки.

- Покупка и закрытие шорта — по ask. Продажа и закрытие лонга — по bid.
- Задержка: заявка живёт с `submit_time + latency_ms`. При нулевой задержке
  рынок исполняется внутри вызова, до возврата в стратегию (выход по времени
  и новый вход на одном тике, как в советнике).
- Лимит исполняется только если цена прошла уровень на `limit_penetration`
  (по умолчанию 0.01 цены, не первое касание). Покупка: `ask <= limit − penetration`.
  Цена исполнения — цена лимита, положительное проскальзывание не отдаётся.
  Ноль в penetration — режим «касание», ближе к тестеру MT5.
- Стоп и SL на гэпе исполняются по фактической худшей цене, не по уровню.
  Тейк — по цене тейка.
- Если на одной миллисекунде (и на отрезке от прошлой котировки) достижимы
  и SL, и TP, берётся стоп, в сделке `ambiguous_sl_tp=1`.
- Срок: тик с временем `>= expiry` снимает заявку до попытки исполнения.
- Уже открытая позиция проверяется до колбэка стратегии. Позиция, открытая
  на этой миллисекунде, видит только цены с тика входа и дальше.

Лимит, который уже «в рынке» в момент постановки, в рыночный не превращается.
Порт алхимика шлёт только рынок, на сверку с ним это не влияет.

## Издержки

Спред — сам тик. Сверху: добавка и множитель спреда, задержка в миллисекундах,
комиссия на сторону лота (в CLI положительное число записывается как расход),
своп.

Своп, если вход был строго раньше момента начисления. Множитель ночи
берётся из `swap_weekday`: понедельник–вторник ×1, среда ×3, четверг и
пятница ×1, суббота и воскресенье ×0. Ночь пятницы поэтому одна.
Знак как в MT5: минус уменьшает результат.

Exness начисляет своп в 17:00 ET, внутри паузы: летом 21:00 UTC, зимой
22:00 UTC (`--swap-clock exness`, это значение по умолчанию). Тестер MT5
в отчёте h1-x12-st кладёт ту же ночь на полночь сервера. Для сверки с
этим отчётом нужен `--swap-clock tester`.

Режим в файле — `SYMBOL_SWAP_MODE_POINTS`. Доллар на лот за ночь считается
так: `points × point × tick_value / tick_size`. Для лонга это
−490.8 × 0.001 × 100 = −49.08 USD, для шорта 0. CLI без `--swap-long` и
`--swap-short` берёт эти числа. Явный `--triple-swap-weekday` отключает
таблицу файла и возвращает старую схему «один день ×3, выходные без ночи».

Число −52 USD на лот за ночь для лонга было подгонкой под шесть ночных
удержаний в отчёте h1-x12-st за август 2026. Оно больше не ставка по
умолчанию. Сверка с тестером пересчитывается со −49.08.

## Сессия

Пауза идёт за Нью-Йорком, не за таблицей `sessions.trade`. Сервер
Exness сидит в UTC+0 и своё летнее время не переводит. По 159 будничным
разрывам тиков 2026 года: последний тик около 16:58 ET, первый после
паузы — медиана 18:00:32 ET, p95 через 158 с после 18:00. Летом это
22:00:30 UTC, зимой около 23:01 UTC.

Сверка по нашим тикам 2026-06-01…10-04 (холдаут не читался) то же самое:
в 20:58–22:00 UTC тиков нет, в будни первый вечерний тик почти всегда
22:00:30. Отчёт тестера стоит на них: выход 8 июня 22:00:30, выход
10 июня 22:00:30, вход 17 июня 22:00:31. Воскресенье 2 августа тестер
закрывает сделку в 22:03:34, первый тик того вечера 22:01:30.

Номинальное окно из дампа 2026-10-24 (`sessions.trade`) открывает вечер
только в 22:01, воскресенье в 22:05. Это позже, чем живая котировка и
чем сделка тестера. Поэтому ворота по умолчанию — «можно торговать с
первого тика после паузы»: сессия открыта с 18:00 ET. Тика раньше нет,
а тик 18:00:32 уже внутри. `--session-gate trade` оставляет номинальные
22:01 и в июне сдвигает те три сделки на 22:01.

`--session-shift` по умолчанию `auto`: лето и зима по правилам DST США
(второе воскресенье марта 07:00 UTC — первое воскресенье ноября 06:00 UTC).
В окне сверки это лето, открытие 22:00 UTC. Зимой открытие 23:00 UTC.
`captured` не сдвигает окна дампа. `winter` всегда добавляет час к
границам паузы. Полночь не двигается. Праздников нет.

SL и TP обрабатываются на любом тике. Вход и выход по времени советника —
только в открытую сессию. В юнит-тестах, где часы золота мешают
арифметике, сессия `AlwaysOpen`.

## Лот

```text
money_per_lot = stop_distance / tick_size * tick_value
lot           = capital * risk_percent / 100 / money_per_lot
```

Пол вниз до шага, затем зажим в [min, max]. Если минимальный лот рискует
больше, чем `risk * max_risk_overshoot`, возвращается 0 и сделка
пропускается. Битый вход (NaN, риск вне (0, 100], стоп ≤ 0, шаг объёма ≤ 0)
даёт `SizingError` и останавливает прогон. В MQL `BrokerCalcLot` на битом
тике возвращает минимальный лот — здесь так не делается.

Общий метод `size_for_risk` умеет и баланс, и средства. Порт алхимика считает
от баланса, потому что советник читает `ACCOUNT_BALANCE`.

## Выходы

`trades.csv`: вход и выход (время, цена), сторона, объём, SL/TP, причина
выхода, гросс, комиссия, своп, нетто, начальный риск, R, спреды, флаг
неоднозначных SL/TP.

```text
R = net_pnl / (|цена_входа − начальный_SL| × объём × money_per_price)
```

Для принятой спецификации XAUUSDm `money_per_price = 100` USD за 1.00 цены
на 1.00 лота. Нет стопа — R пустой, в метрики R сделка не входит
(`r_undefined`), в денежный профит-фактор входит.

`equity.csv` — события (вход, выход, своп, закрытие выбранного ТФ) и точка
дна equity. Скаляр просадки по средствам считается на каждом тике, даже если
кривая записана реже.

Метрики в `metrics.json` и `summary.txt`, подписи разные:

- просадка по балансу — только от изменений баланса;
- просадка по средствам — плавающий результат на каждом тике.

Плюс нетто в деньгах и в R, профит-фактор в деньгах и в R, винрейт, средний R,
число сделок, самая длинная серия убыточных закрытий. Бутстрэп: выборка сделок
с возвращением, перцентильный 95% интервал, по умолчанию 2000 выборок, seed 1.
Бесконечный профит-фактор в JSON — `null` и флаг `*_infinite`.

## Спецификация XAUUSDm

`xauusd_exness()` читает `data/symbol-spec/XAUUSDm.json`. Файла нет —
загрузка падает, числа из кода не подставляются. Выгрузка терминала
Exness, build 6283, снята 2026-10-24T08:40:41Z, сервер UTC+0.

Контракт 100, digits 3, point 0.001, tick_size 0.001, tick_value 0.1
(прибыль и убыток совпадают), лот 0.01…200 шаг 0.01, стоп-уровень 0,
freeze level 0. Плечо в прогоне задаётся отдельно, по умолчанию 2000.
`money_per_price = tick_value / tick_size = 100` USD за 1.00 цены на
1.00 лота. `adjusted_point` при 3 и 5 знаках равен point, при 2 и 4 —
point/10. Минимальный стоп варианта h1-x12-st: 1000 × 0.001 = 1.00 USD.

Стоп-уровень брокера проверяется только если в файле он больше нуля:
SL или TP ближе, чем `stops_level × point`, заявка отклоняется. В этой
выгрузке уровень 0, проверки нет. Freeze level записан и тоже 0; перенос
стопа внутри ненулевого freeze модель не делает, потому что порт стоп
после входа не двигает.

Проверка денег по отчёту: шорт, выход хуже стопа на 0.143, объём 0.02 →
лишние 0.286 USD убытка. Это 0.143 × 0.02 × 100.

## Порт советника

Интерфейс: `required_timeframes`, `on_start`, `on_bar_close`, `on_tick`.
Контекст даёт тик, закрытые бары, открытие формирующегося бара, сессию,
баланс, средства, одну позицию, постановку заявок и лот.

Сделан один порт: `hybrid/hybrid-alchemist_v1.0.mq5`, вариант `h1-x12-st`
(`backtester/strategies/alchemist.py`). Источник — MQL, не `screen.py`.

Заводские входы варианта: H1, SMA 200, HMA 21, CCI 20 ±100, H4 EMA 50,
обе стороны, выход через 12 баров, противоположный сигнал выключен, ATR 14,
стоп max(3×ATR, 1000 пунктов), тейк выключен, фильтр дня — структура
(длина 5), риск 1% баланса, перебор риска 1.5, спред не шире 10% дистанции
стопа, magic 71012, комментарий HAL. Режим, новости, трейлинг и закрытие
по проскальзыванию в этом варианте выключены; если включить их в конфиге,
порт падает, а не молча игнорирует фильтр.

Сигнал — смена состояния двух последних закрытых баров H1. Свежий ноль не
стирает заявку, которая ждёт открытия сессии. Тренд D1 считается один раз,
на открытии формирующегося H1. ATR читается в момент входа. Стоп и тейк
считаются от цены решения (ask для лонга, bid для шорта) и к более позднему
исполнению не подтягиваются.

H4: индекс — последний H4, закрытый к началу сигнального H1
(`iBarShift + 1`), с учётом формирующегося H4. Пример: H1 13:00, текущий H4
открыт в 12:00, закрытые …08:00 → берётся 08:00. H1 ровно в 12:00 тоже
смотрит на 08:00.

Структура D1 повторяет `MarketStructure.mqh`: окно (400+5)×2 суток,
воскресенье сливается с понедельником, слева равенство ломает пивот,
справа нужно строгое неравенство. Тики Exness начинаются с 2026-01-01,
поэтому без прогрева окно короче, чем у тестера.

## Прогрев Dukascopy

Публичные свечи BID M1: `datafeed.dukascopy.com`, путь
`/datafeed/XAUUSD/{год}/{месяц-1}/{день}/BID_candles_min_1.bi5`.
Файл — LZMA, запись 24 байта: секунды от полуночи UTC, open, close, low,
high целыми, объём. Цена XAUUSD = целое / 1000. Каталог на диске —
`YYYY/MM/DD.bi5`. В git он не кладётся. Сутки с 2026-10-16 загрузчик не читает.

Минуты вне сессии Exness выбрасываются. Иначе суббота, где Dukascopy
повторяет одну цену каждую минуту, стала бы дневным баром и сломала склейку
воскресенья. Из оставшихся минут собираются H1, H4 и D1. Это только история
индикаторов: заявок по прогреву нет, ask у этих баров равен bid.

Сдвиг на уровень Exness считается по пересечению, не подгоняется под отчёт:

```text
offset = median(close_M1_bid_Exness − close_M1_bid_Dukascopy)
```

по общим минутам сессии. Окно измерения — 2026-01-02…2026-01-08 (до холдаута).
Команда:

```bash
python3 -m backtester.cli offset \
  --dukascopy /path/dukascopy-m1 \
  --ticks /path/ticks_XAUUSDm_2026-01.csv.gz \
  --start 2026-01-02 --to 2026-01-08
```

Полученную медиану передают как `--warmup-offset`. OHLC прогрева сдвигаются
на неё целиком. У бара поле `source`: `dukascopy` у прогрева, `exness` у баров
из тиков.

Граница. Первый тик Exness открывает живой бар. Прогрев отдаёт только те бары,
которые к этому открытию уже закрыты. Последний бар прогрева кончается ровно
в открытие живого, либо дыра между ними целиком лежит в закрытой сессии
(пауза котировок 20:58–22:00; у таблицы trade это 20:58–22:01;
при `--session-shift winter` границы паузы сдвигаются на час).
Общего времени у двух источников нет. День
2026-01-01 до первого тика добирается из Dukascopy, сам дневной бар 1 января
строится уже из тиков Exness.

```bash
python3 -m backtester.cli alchemist \
  --ticks /path/ticks_XAUUSDm_2026-01.csv.gz \
  --source exness \
  --warmup-dukascopy /path/dukascopy-m1 \
  --warmup-offset 0.2 \
  --data-from 2026-01-01 \
  --trade-from 2026-06-01 \
  --to 2026-10-04 \
  --out /tmp/alch-h1-x12-st
```

Число `0.2` в примере — порядок величины. В прогон подставляется медиана
команды `offset`, она же пишется в `metrics.json` → `warmup.offset`.

Прогон (тики снаружи репозитория; `--to` — последний день включительно):

```bash
python3 -m backtester.cli alchemist \
  --ticks /path/ticks-2026-01.csv.gz /path/ticks-2026-02.csv.gz \
  --source exness \
  --data-from 2026-01-01 \
  --trade-from 2026-06-01 \
  --to 2026-10-04 \
  --latency-ms 200 \
  --session-shift auto \
  --swap-clock tester \
  --deposit 10000 \
  --out /tmp/alch-spec-swap
```

Своп в долларах здесь не задан: лонг −49.08 и шорт 0 приходят из
спецификации. `--swap-clock tester` оставляет начисление на полночь
сервера, как в отчёте MT5. Без этого флага своп встаёт в 17:00 ET.
Чтобы повторить старую подгонку −52, нужны `--swap-long -52 --swap-short 0`.

Повтор прогона h1-x12-st на тиках Exness, 2026-06-01…10-04, задержка
200 мс, депозит 10 000, сдвиг `captured` (в этом летнем окне он совпадает
с `auto`), начисление свопа в полночь сервера. Против прогона со ставкой
−52 на тех же шести ночных лонгах своп −4.68 стал −4.42 (ровно ×49.08/52).
Просадка в деньгах не сдвинулась: баланс 356.80, средства 415.06. Проценты
чуть ниже, потому что пик баланса вырос. В отчёте MT5 своп −5.17 сидит
ближе к подгонке −52, чем к −49.08 из дампа 2026-10-24: ночи в HTML другие
(другой набор сделок августа), а ставка ночи там около −52, не −49.08.

Тот замер был с воротами `trade` (открытие в 22:01). Три шорта июня,
которые у тестера стоят на тике 22:00:30, из-за этого уехали на 22:01
и дали +1.76 к нетто сверх свопа. С воротами `quote` эти тики снова
внутри сессии. Суммарное нетто того прогона 296.95 → 298.97, пар с
отчётом 44 / 4 / 7. Расхождений по времени выхода в строгом профиле
было 8 вместо 6 именно из-за двух выходов в 22:01.

Интервал, который задевает 2026-10-16 и позже, команда не читает без
`--allow-holdout`. Правило — в `docs/oos-protocol.md`.

Сверка со списком сделок тестера:

```bash
python3 -m backtester.cli compare \
  --ours /tmp/alch-h1-x12-st/trades.csv \
  --mt5 /path/h1-x12-st.htm \
  --start 2026-06-01 \
  --end 2026-10-04 \
  --out /tmp/alch-h1-x12-st/compare.json
```

HTML (UTF-8 или UTF-16) и JSON (`trades` или `deals`). Строка balance не
сделка. Стоп, если он есть, берётся из комментария `sl 4035.980`. Пара —
та же сторона, вход в пределах 180 с и 3.00 цены. Окно — по времени входа,
конец исключительный.

Два профиля допуска, `--profile`:

- `strict` (он же набор флагов по умолчанию): время входа >2 с, цена входа,
  выхода или стопа >0.05, время выхода >5 с, объём >0.001.
- `aligned`: время входа >5 с и цена >0.50. Так золото, сдвинувшееся за
  доли секунды после задержки тестера 200 мс, не заполняет список причин.
  Время выхода по-прежнему 5 с, объём по-прежнему 0.001: другой бар выхода
  и другой шаг лота остаются расхождением.
- `both` печатает оба профиля.

## Чего модель не делает

- Праздники, реквоты, частичное исполнение, плавающая задержка.
  Стоп-уровень из выгрузки равен 0 и поэтому сделки не режет; ненулевой
  уровень из файла режет слишком близкий SL/TP. Freeze level тоже 0.
- Прошлые ставки свопа. В прогоне одна таблица — та, что снята
  2026-10-24. Зимний сдвиг сессии (`winter` и `auto`) гипотеза: дамп
  летний, отдельной зимней выгрузки нет.
- Перевод уже рыночного лимита в рынок, как в `TradeExecutor.mqh`.
- Лимит риска на весь счёт (`MaxAccountRiskPercent`, в варианте 0).
- Режим, новости, трейлинг, закрытие по проскальзыванию.
- Годы 2024–2025 отчётов MT5: там модель OHLC M1, не реальные тики.
  Спред в поле бара — не спред тика. Сверять их с этим прогоном нельзя.
- Кривая на диске реже, чем тик. Число просадки по средствам — по тикам.
