# Тиковый бэктестер XAUUSD

Независимая модель исполнения. Тестер MetaTrader сюда не входит: ни его сделки,
ни его индикаторные буферы, ни его отчёты не считаются истиной. Отчёты в
`tester-results` нужны только как внешняя сверка.

Запуск и тесты — из этого каталога:

```bash
cd research/backtester
python3 -m pytest
python3 -m backtester.cli alchemist --help
python3 -m backtester.cli compare --help
```

Зависимостей у ядра нет. Чтение parquet (Dukascopy) требует `pyarrow` 14–17
(`pip install 'pyarrow>=14,<18'` рядом с numpy 1.x). Тесты — pytest.

Сырые тики в репозиторий не кладутся. В `tests/fixtures` только короткий HTML
отчёта на несколько строк.

## Поток тиков

Один тип `Tick`: `time_msc` (UTC, миллисекунды), `bid`, `ask`.

- Exness: `csv.gz`, колонки `time_msc,bid,ask,last,volume,flags`
  (`volume_real` допустим и не обязателен). Время сервера Exness — UTC+0,
  своего перехода на летнее время нет. Реальные тики XAUUSDm у брокера есть
  с 2026-01-01.
- Dukascopy: parquet (zstd), колонки `time_msc,bid,ask,bid_vol,ask_vol`.

Файлы читаются по порядку путей. `end_msc` исключительный: тик на границе
и всё, что позже, не отдаётся. Время, идущее назад, обрывает поток.

Поправка котировки (сначала ширина спреда, потом сдвиг уровня):

```text
mid  = (bid + ask) / 2
half = (ask - bid) * spread_multiplier / 2
bid' = mid - half - spread_addon / 2 + price_offset
ask' = mid + half + spread_addon / 2 + price_offset
```

`spread_addon` расширяет спред вокруг середины. `price_offset` сдвигает обе
стороны. Пример: bid 100, ask 100.4, множитель 2, добавка 0.2, сдвиг 0.2 →
bid 99.9, ask 100.9. Если после поправки bid > ask, прогон останавливается.

Чтобы прикинуть Exness на архиве Dukascopy, типичная пара — `price_offset=0.2`
и `spread_addon` под нужный спред. Медиана спреда Dukascopy по годам: 0.39 /
0.60 / 0.68 USD в 2024 / 2025 / 2026. Это ориентир, не подгонка под отчёт.

## Бары

M1, M2, M5, M15, M30, H1, H2, H3, H4, H6, H8, H12, D1. Сетка от эпохи UTC.
Тик ровно на границе открывает новый бар и в предыдущий не попадает.
Пустой интервал бара не создаёт. OHLC — bid, ask копится отдельно.

Стратегия видит только закрытые бары. На общей границе сначала закрывается
старший таймфрейм, потом младший. Прогрев (`--warmup-m1`, CSV
`time,open,high,low,close` по bid) подмешивает бары, которые полностью
закрылись до первого тика.

## Заявки и защита

Рынок, лимит, стоп, SL, TP, срок жизни заявки.

- Покупка и закрытие шорта — по ask. Продажа и закрытие лонга — по bid.
- Задержка: заявка живёт с `submit_time + latency_ms`. При нулевой задержке
  рынок исполняется внутри вызова, до возврата в стратегию (выход по времени
  и новый вход на одном тике, как в советнике).
- Лимит исполняется только если цена прошла уровень на `limit_penetration`
  (по умолчанию 0.01 цены, не первое касание). Покупка: `ask <= limit − penetration`.
  Цена исполнения — цена лимита, положительное проскальзывание не отдаётся.
  Ноль в penetration — режим «касание», ближе к тестеру MT5.
- Стоп и SL на гэпе исполняются по фактической худшей цене, не по уровню.
  Тейк — по цене тейка.
- Если на одной миллисекунде (и на отрезке от прошлой котировки) достижимы
  и SL, и TP, берётся стоп, в сделке `ambiguous_sl_tp=1`.
- Срок: тик с временем `>= expiry` снимает заявку до попытки исполнения.
- Уже открытая позиция проверяется до колбэка стратегии. Позиция, открытая
  на этой миллисекунде, видит только цены с тика входа и дальше.

Лимит, который уже «в рынке» в момент постановки, в рыночный не превращается.
Порт алхимика шлёт только рынок, на сверку с ним это не влияет.

## Издержки

Спред — сам тик. Сверху: добавка и множитель спреда, задержка в миллисекундах,
комиссия на сторону лота (в CLI положительное число записывается как расход),
своп.

Своп в полночь UTC, если вход был строго раньше. Суббота и воскресенье
отдельной ночи не дают. Ночь пятницы — одна, даже если следующий тик уже
понедельник. Среда (день 2, понедельник = 0) по умолчанию ×3. Знак как в MT5:
минус уменьшает результат. Ставка по умолчанию 0. Число −52 USD на лот за ночь
для лонга и 0 для шорта — подгонка под шесть ночных удержаний в отчёте
h1-x12-st за август 2026, не расписание брокера.

## Сессия

`ExnessGoldSession` — пауза COMEX 17:00–18:00 Нью-Йорка, выведенная из дыр
котировок и часов входов в отчёте, а не из `SymbolInfoSessionTrade`.

- Лето США (EDT): закрыто [21:00, 22:00) UTC.
- Зима (EST): закрыто [22:00, 23:00) UTC.
- Пятница закрывается в начале паузы до воскресенья. Суббота закрыта.
- DST: второе воскресенье марта 07:00 UTC — первое воскресенье ноября 06:00 UTC.
  В 2026 это 8 марта 07:00 и 1 ноября 06:00.

SL и TP обрабатываются на любом тике. Вход и выход по времени советника —
только в открытую сессию. Праздников нет. В юнит-тестах сессия `AlwaysOpen`,
чтобы часы золота не мешали арифметике.

## Лот

```text
money_per_lot = stop_distance / tick_size * tick_value
lot           = capital * risk_percent / 100 / money_per_lot
```

Пол вниз до шага, затем зажим в [min, max]. Если минимальный лот рискует
больше, чем `risk * max_risk_overshoot`, возвращается 0 и сделка
пропускается. Битый вход (NaN, риск вне (0, 100], стоп ≤ 0, шаг объёма ≤ 0)
даёт `SizingError` и останавливает прогон. В MQL `BrokerCalcLot` на битом
тике возвращает минимальный лот — здесь так не делается.

Общий метод `size_for_risk` умеет и баланс, и средства. Порт алхимика считает
от баланса, потому что советник читает `ACCOUNT_BALANCE`.

## Выходы

`trades.csv`: вход и выход (время, цена), сторона, объём, SL/TP, причина
выхода, гросс, комиссия, своп, нетто, начальный риск, R, спреды, флаг
неоднозначных SL/TP.

```text
R = net_pnl / (|цена_входа − начальный_SL| × объём × money_per_price)
```

Для принятой спецификации XAUUSDm `money_per_price = 100` USD за 1.00 цены
на 1.00 лота. Нет стопа — R пустой, в метрики R сделка не входит
(`r_undefined`), в денежный профит-фактор входит.

`equity.csv` — события (вход, выход, своп, закрытие выбранного ТФ) и точка
дна equity. Скаляр просадки по средствам считается на каждом тике, даже если
кривая записана реже.

Метрики в `metrics.json` и `summary.txt`, подписи разные:

- просадка по балансу — только от изменений баланса;
- просадка по средствам — плавающий результат на каждом тике.

Плюс нетто в деньгах и в R, профит-фактор в деньгах и в R, винрейт, средний R,
число сделок, самая длинная серия убыточных закрытий. Бутстрэп: выборка сделок
с возвращением, перцентильный 95% интервал, по умолчанию 2000 выборок, seed 1.
Бесконечный профит-фактор в JSON — `null` и флаг `*_infinite`.

## Спецификация XAUUSDm

`xauusd_exness()` — допущение, не дамп `SymbolInfo`: digits 3, point 0.001,
контракт 100, tick_size 0.001, tick_value 0.1, лот 0.01…100 шаг 0.01,
плечо 2000. `adjusted_point` при 3 и 5 знаках равен point, при 2 и 4 — point/10.
Минимальный стоп варианта h1-x12-st: 1000 × 0.001 = 1.00 USD.

Проверка по отчёту: шорт, выход хуже стопа на 0.143, объём 0.02 → лишние
0.286 USD убытка. Это 0.143 × 0.02 × 100.

## Порт советника

Интерфейс: `required_timeframes`, `on_start`, `on_bar_close`, `on_tick`.
Контекст даёт тик, закрытые бары, открытие формирующегося бара, сессию,
баланс, средства, одну позицию, постановку заявок и лот.

Сделан один порт: `hybrid/hybrid-alchemist_v1.0.mq5`, вариант `h1-x12-st`
(`backtester/strategies/alchemist.py`). Источник — MQL, не `screen.py`.

Заводские входы варианта: H1, SMA 200, HMA 21, CCI 20 ±100, H4 EMA 50,
обе стороны, выход через 12 баров, противоположный сигнал выключен, ATR 14,
стоп max(3×ATR, 1000 пунктов), тейк выключен, фильтр дня — структура
(длина 5), риск 1% баланса, перебор риска 1.5, спред не шире 10% дистанции
стопа, magic 71012, комментарий HAL. Режим, новости, трейлинг и закрытие
по проскальзыванию в этом варианте выключены; если включить их в конфиге,
порт падает, а не молча игнорирует фильтр.

Сигнал — смена состояния двух последних закрытых баров H1. Свежий ноль не
стирает заявку, которая ждёт открытия сессии. Тренд D1 считается один раз,
на открытии формирующегося H1. ATR читается в момент входа. Стоп и тейк
считаются от цены решения (ask для лонга, bid для шорта) и к более позднему
исполнению не подтягиваются.

H4: индекс — последний H4, закрытый к началу сигнального H1
(`iBarShift + 1`), с учётом формирующегося H4. Пример: H1 13:00, текущий H4
открыт в 12:00, закрытые …08:00 → берётся 08:00. H1 ровно в 12:00 тоже
смотрит на 08:00.

Структура D1 повторяет `MarketStructure.mqh`: окно (400+5)×2 суток,
воскресенье сливается с понедельником, слева равенство ломает пивот,
справа нужно строгое неравенство. Если история тиков короче этого окна,
фильтр дня не совпадёт с тестером, у которого бары были и до 2026.

Прогон (тики снаружи репозитория; `--to` — последний день включительно):

```bash
python3 -m backtester.cli alchemist \
  --ticks /path/ticks-2026-01.csv.gz /path/ticks-2026-02.csv.gz \
  --source exness \
  --data-from 2026-01-01 \
  --trade-from 2026-06-01 \
  --to 2026-10-05 \
  --latency-ms 200 \
  --swap-long -52 \
  --swap-short 0 \
  --deposit 10000 \
  --out /tmp/alch-h1-x12-st
```

Интервал, который задевает 2026-10-16 и позже, команда не читает без
`--allow-holdout`. Правило — в `docs/oos-protocol.md`.

Сверка со списком сделок тестера:

```bash
python3 -m backtester.cli compare \
  --ours /tmp/alch-h1-x12-st/trades.csv \
  --mt5 /path/h1-x12-st.htm \
  --start 2026-06-01 \
  --end 2026-10-05 \
  --out /tmp/alch-h1-x12-st/compare.json
```

HTML (UTF-8 или UTF-16) и JSON (`trades` или `deals`). Строка balance не
сделка. Стоп, если он есть, берётся из комментария `sl 4035.980`. Пара —
та же сторона, вход в пределах 180 с и 3.00 цены. Дальше причины, если
разошлись время входа (>2 с), цена входа или выхода (>0.05), время выхода
(>5 с), объём (>0.001) или стоп (>0.05). Окно — по времени входа, конец
исключительный.

## Чего модель не делает

- Праздники, стоп-уровень брокера, реквоты, частичное исполнение,
  плавающая задержка.
- Историческое расписание свопа. Ставка задаётся снаружи.
- Перевод уже рыночного лимита в рынок, как в `TradeExecutor.mqh`.
- Лимит риска на весь счёт (`MaxAccountRiskPercent`, в варианте 0).
- Режим, новости, трейлинг, закрытие по проскальзыванию.
- Годы 2024–2025 отчётов MT5: там модель OHLC M1, не реальные тики.
  Спред в поле бара — не спред тика. Сверять их с этим прогоном нельзя.
- Кривая на диске реже, чем тик. Число просадки по средствам — по тикам.
